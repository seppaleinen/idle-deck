## Decision

The MVP is written in **Go 1.27** (installed locally: `go1.27.1 darwin/arm64`).

## Rationale

A long-running daemon with a worker pool and subprocess supervision is exactly Go's strength; a
single static binary suits a personal daemon. The concurrency model (goroutines + channels) matches
the worker/queue/lease design that the architecture tickets are converging on.

## Alternatives considered

- Python + uv — rejected at charting (Q5 chose Go): faster to prototype, but the worker-pool daemon
  is a long-lived process where Go's supervision story is stronger.
- TypeScript + bun — rejected: only wins if the GUI (#2) ships in the MVP, which D19 rules out.

## Consequences

- Single static binary for the daemon.
- Go naming conventions apply (`Harness`, not `BaseHarness`) — the interface naming is D18,
  pending #6.
